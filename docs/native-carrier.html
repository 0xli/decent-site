The verified build used a cached copy of that tarball. Its SHA-256, 9a6276d8c4e5202b972d45819fd0b47ff9b55750c8f35a83d54f3ca4a4726381, matches the pin in deps/toxcore/CMakeLists.txt. Every other dependency downloaded from its public URL. Until a replacement source is published, a new developer cannot finish the build below without that file.

The native Carrier SDK is the C library under every non-JavaScript Decent Network client. It gives a process a self-generated Carrier identity (address, user ID) on the Carrier DHT. On top of that it provides friends and presence, text and binary messages with delivery receipts, and offline delivery through Express nodes. It also covers invites, groups, file transfer, and peer-to-peer sessions with streams and TCP port forwarding. The Beagle Chat iOS and Android apps ship it from the feat/agentnet-proto-v2 branch. The iOS app gets it through the Swift Carrier SDK and the Android app through the Android Carrier SDK. The API is plain C (carrier.h, carrier_session.h, carrier_filetransfer.h) and can be called from C++ as is.

When to use it

Use it from C or C++ on macOS or Linux, for example in a daemon, a sidecar, or an embedded device, or as the base of a new language binding. On iOS use the Swift Carrier SDK, and on Android use the Android Carrier SDK; both wrap this library. In Node.js or a browser use @decentnetwork/peer, a separate JavaScript implementation of the same wire protocol.

Which branch to use. No GitHub releases or prebuilt libraries are published for either public repository (gh release list is empty for both). The tags (release-v5.x, elastos-carrier-native-5.1, …) are upstream Elastos releases from 2018–2019 and predate this network's protocol work. Use the feat/agentnet-proto-v2 branch of 0xli/Elastos.NET.Carrier.Native.SDK. That is the branch the shipping Beagle apps are built from, and its docs/AGENTNET_PROTOCOL.md documents byte compatibility with @decentnetwork/peer. The other branches are behind it:

Add it to your project

No prebuilt distribution exists, so build from source. On macOS you need Xcode command-line tools, CMake, and brew install autoconf automake libtool shtool pkg-config gettext. On Debian/Ubuntu, the README lists build-essential autoconf automake autopoint libtool flex bison libncurses5-dev cmake. The commands below are the ones run for the verification, on Apple silicon; the build took about 2 minutes with -j8.

git clone --branch feat/agentnet-proto-v2 https://github.com/0xli/Elastos.NET.Carrier.Native.SDK.git
cd Elastos.NET.Carrier.Native.SDK

# Dependency tarballs are cached here. c-toxcore must be placed by hand (see the note at the top).
mkdir -p build/.tarballs
cp /path/to/c-toxcore-0.2.12.carrier.tar.gz build/.tarballs/

cmake -S . -B build/macos-arm64 -DCMAKE_BUILD_TYPE=Release \
      -DENABLE_SHARED=ON -DENABLE_STATIC=ON -DENABLE_APPS=ON -DENABLE_TESTS=OFF \
      -DCMAKE_INSTALL_PREFIX=$PWD/../carrier-dist
make -C build/macos-arm64 -j8
make -C build/macos-arm64 install

A failed download leaves a 0-byte file in build/.tarballs/, and the next configure treats it as cached. Delete any empty file there before retrying.

Initialize

Fill a CarrierOptions with a data directory and the network's bootstrap nodes. Optionally add Express nodes for offline delivery. Register the callbacks you need, call carrier_new, then run carrier_run on its own thread. Use the bootstrap and Express nodes from config/carrier.conf on the branch. The program below uses three of them.

#include <stdio.h>
#include <string.h>
#include <pthread.h>
#include <unistd.h>
#include <carrier.h>

static void on_connection(Carrier *c, CarrierConnectionStatus status, void *ctx)
{
    printf("connection: %s\n",
           status == CarrierConnectionStatus_Connected ? "connected" : "disconnected");
}

static void on_ready(Carrier *c, void *ctx)
{
    printf("ready\n");
}

static void on_friend_request(Carrier *c, const char *userid,
                              const CarrierUserInfo *info, const char *hello, void *ctx)
{
    printf("friend request from %s: %s\n", userid, hello);
    carrier_accept_friend(c, userid);
}

static void on_friend_message(Carrier *c, const char *from, const void *msg, size_t len,
                              int64_t timestamp, bool offline, void *ctx)
{
    printf("%s from %s: %.*s\n", offline ? "offline msg" : "msg", from, (int)len,
           (const char *)msg);
}

static void *run_loop(void *arg)
{
    carrier_run((Carrier *)arg, 10);   /* blocks until carrier_kill() */
    return NULL;
}

int main(int argc, char *argv[])
{
    BootstrapNode bootstraps[] = {
        { "13.58.208.50",  NULL, "33445", "89vny8MrKdDKs7Uta9RdVmspPjnRMdwMmaiEW27pZ7gh" },
        { "18.216.102.47", NULL, "33445", "G5z8MqiNDFTadFUPfMdYsYtkUDbX5mNCMVHMZtsCnFeb" },
        { "52.57.248.163", NULL, "33445", "CfJLve8FNQPQJ9xYQ8oEVkPxeAPCN7iSdhnYFkWmWgLn" },
    };
    ExpressNode express[] = {
        { "lens.beagle.chat", NULL, "443", "ECbs4GxwGzxGerNkmqDJFibEmevu8jAXqAZtikccvD95" },
    };
    CarrierOptions opts;
    CarrierCallbacks cbs;
    char addr[CARRIER_MAX_ADDRESS_LEN + 1];
    char userid[CARRIER_MAX_ID_LEN + 1];
    char nodeid[CARRIER_MAX_ID_LEN + 1];
    char err[128];
    pthread_t tid;

    memset(&opts, 0, sizeof(opts));
    opts.persistent_location = argc > 1 ? argv[1] : "./carrier-data";
    opts.udp_enabled = true;
    opts.log_level = CarrierLogLevel_Warning;
    opts.bootstraps = bootstraps;
    opts.bootstraps_size = sizeof(bootstraps) / sizeof(bootstraps[0]);
    opts.express_nodes = express;
    opts.express_nodes_size = sizeof(express) / sizeof(express[0]);

    memset(&cbs, 0, sizeof(cbs));
    cbs.connection_status = on_connection;
    cbs.ready = on_ready;
    cbs.friend_request = on_friend_request;
    cbs.friend_message = on_friend_message;

    Carrier *c = carrier_new(&opts, &cbs, NULL);
    if (!c) {
        printf("carrier_new failed: %s\n",
               carrier_get_strerror(carrier_get_error(), err, sizeof(err)));
        return 1;
    }

    printf("version: %s\n", carrier_get_version());
    printf("address: %s\n", carrier_get_address(c, addr, sizeof(addr)));
    printf("userid:  %s\n", carrier_get_userid(c, userid, sizeof(userid)));
    printf("nodeid:  %s\n", carrier_get_nodeid(c, nodeid, sizeof(nodeid)));

    pthread_create(&tid, NULL, run_loop, c);
    sleep(argc > 2 ? atoi(argv[2]) : 15);
    carrier_kill(c);
    pthread_join(tid, NULL);
    printf("killed\n");
    return 0;
}

The first run creates carrier.data in persistent_location. That file holds the identity, unencrypted, plus the friend list. Later runs reuse it. carrier_get_version() returns major, minor and the first six hex digits of the build checkout's local master, with no separators (5 2 19aac2 above). It does not identify the branch you built.

Identity

Each node's identity is a key pair kept in carrier.data. The user ID is the base58 public key. The address (52 characters) is the user ID plus a nospam value and checksum. Others need the address to send a friend request; after that they reach you by user ID. The node ID equals the user ID on this build. Changing the nospam value with carrier_set_self_nospam changes the address, so old copies of it stop working for new requests.

The proto v2 API adds XEdDSA signatures that the JavaScript peer can verify (curve25519-js), plus secret-key export and import. The excerpt below is from a program that was run:

const char *msg = "decent-auth\nhttps://example.org\nnonce-123";
uint8_t sig[CARRIER_IDENTITY_SIGNATURE_BYTES], secret[CARRIER_IDENTITY_SECRET_BYTES];

carrier_identity_sign(c, (const uint8_t *)msg, strlen(msg), sig);
/* 1 = valid, 0 = invalid, -1 = bad arguments; needs only the userid */
int ok = carrier_identity_verify(userid, (const uint8_t *)msg, strlen(msg), sig);

carrier_export_secret_key(c, secret);   /* keep it in a keychain, never a plain file */
/* Import: a fresh persistent_location plus opts.secret_key = secret gives the same userid. */

verify good: 1
verify tampered: 0

Profile: carrier_set_self_info / carrier_get_self_info take a CarrierUserInfo (name, description, gender, phone, email, region). Beagle clients put the CryptoPunk avatar ID in gender. carrier_set_self_profile_ext adds avatar_url, url, ens and extra. carrier_set_client_info advertises platform, os_version, app_version and proto_version. Set proto_version to 2 only if your app answers the DNPACK1 text acknowledgements that @decentnetwork/peer sends. Read a friend's values with carrier_get_friend_client_info and carrier_get_friend_profile_ext.

Friends

carrier_add_friend(c, address, hello) sends a request. The other side gets friend_request and calls carrier_accept_friend(c, userid). On the requester, friend_added fired right after the request was sent. friend_connection reports when a friend comes online or goes offline. This excerpt is from a two-node program that was run, with both nodes in one process:

/* B */
if (!carrier_is_friend(b, a_id) && carrier_add_friend(b, a_addr, "hi from B") < 0)
    printf("[B] add_friend failed: 0x%x\n", carrier_get_error());

Messages

carrier_send_friend_message sends up to CARRIER_MAX_APP_BULKMSG_LEN (16 MB). Messages over 1024 bytes are fragmented and reassembled for you. The library refuses messages over 5 MB to a friend that advertises protocol version 0. The receipt callback reports one of three states: CarrierReceipt_ByFriend (delivered online), CarrierReceipt_Offline (stored on an Express node), or CarrierReceipt_Error.

static void on_receipt(uint32_t msgid, CarrierReceiptState state, void *ctx)
{
    printf("[B] receipt for msg %u: %s\n", msgid,
           state == CarrierReceipt_ByFriend ? "ByFriend" :
           state == CarrierReceipt_Offline ? "Offline" : "Error");
}

uint32_t msgid;
if (carrier_send_friend_message(b, a_id, "hello A", 7, &msgid, on_receipt, NULL) < 0)
    printf("[B] send failed: 0x%x\n", carrier_get_error());

[A] message from FXP4Vu7zdMBjbPbkjtyryh7rMLtGFAbf5bPciY7xNpy2 (offline=0): hello A

Incoming messages arrive on friend_message(carrier, from, msg, len, timestamp, offline, context). The header documents timestamp as seconds since the Epoch. The source passes microseconds, and the run above saw 1793954355618750, so treat it as microseconds. If a message gets no receipt within CARRIER_RECEIPT_TIMEOUT_SECONDS (30 s), the library re-sends it through Express.

Files

carrier_filetransfer.h (link -lcarrierfiletrans -lcarriersession) is a pull-driven, resumable transfer over a session stream. Each side calls carrier_filetransfer_init once; the receiver passes a connect callback. The sender opens a transfer with the file info and connects. The receiver accepts, gets file, and pulls from an offset. The sender gets pull and calls carrier_filetransfer_send. The excerpt below was run:

For large files, send from a separate thread in chunks of at most CARRIER_MAX_USER_DATA_LEN (2048 bytes). That is what the library's internal easyfile.c helper does; it is not exported. This file transfer is native to native only. Beagle apps and @decentnetwork/peer send online files as inline bulk messages (up to 16 MB, through carrier_send_friend_message), wrapped in an application-level JSON envelope. The JavaScript peer's messenger file transfer (packet IDs 80–82) is not implemented in this SDK. See docs/AGENTNET_PROTOCOL.md §2 on the branch.

Sessions and calls

carrier_session.h (link -lcarriersession) sets up ICE (pjnath) peer-to-peer sessions with a friend: direct, server-reflexive, or relayed. A session carries one or more streams. Stream options: CARRIER_STREAM_PLAIN, CARRIER_STREAM_RELIABLE, CARRIER_STREAM_MULTIPLEXING, and CARRIER_STREAM_PORT_FORWARDING. Multiplexing streams carry channels (carrier_stream_open_channel, carrier_stream_write_channel). Port-forwarding streams expose a local TCP service (carrier_session_add_service) that the peer opens with carrier_stream_open_port_forwarding. This library has no audio/video call API. Beagle calls use the WebRTC SDKs, which signal over Carrier messages.

The handshake:

  1. Both sides call carrier_session_init(carrier). The receiving side registers carrier_session_set_callback(carrier, NULL, on_request, ctx).
  2. Caller: carrier_session_new(carrier, peer_userid), then carrier_session_add_stream(...). Wait for CarrierStreamState_initialized, then call carrier_session_request(session, NULL, on_complete, ctx).
  3. Callee, in or after on_request(from, bundle, sdp, len): carrier_session_new, then the same add_stream. Wait for initialized, call carrier_session_reply_request(session, NULL, 0, NULL), wait for transport_ready, then call carrier_session_start(session, sdp, len).
  4. Caller, in on_complete(…, status == 0, sdp, len): wait for transport_ready, then call carrier_session_start(session, sdp, len).
  5. Both streams reach CarrierStreamState_connected. Then use carrier_stream_write and the stream_data callback.

The excerpt below is from a program that was run. Both nodes ran in one process, and its main thread waited for the stream states:

CarrierStreamCallbacks scb;
memset(&scb, 0, sizeof(scb));
scb.state_changed = on_state;      /* records the state per side */
scb.stream_data   = on_data;

/* B (caller) */
B.s = carrier_session_new(b, a_id);
B.stream = carrier_session_add_stream(B.s, CarrierStreamType_text,
                                      CARRIER_STREAM_RELIABLE, &scb, &B);
wait_state(&B, CarrierStreamState_initialized, 30);
carrier_session_request(B.s, NULL, b_on_complete, NULL);   /* b_on_complete saves A's SDP */

/* A (callee), after a_on_request saved `from` and B's SDP */
A.s = carrier_session_new(a, A.from);
A.stream = carrier_session_add_stream(A.s, CarrierStreamType_text,
                                      CARRIER_STREAM_RELIABLE, &scb, &A);
wait_state(&A, CarrierStreamState_initialized, 30);
carrier_session_reply_request(A.s, NULL, 0, NULL);
wait_state(&A, CarrierStreamState_transport_ready, 30);
carrier_session_start(A.s, A.remote_sdp, A.sdp_len);

/* B */
wait_state(&B, CarrierStreamState_transport_ready, 30);
carrier_session_start(B.s, B.remote_sdp, B.sdp_len);
wait_state(&B, CarrierStreamState_connected, 60);

Send the session request only after the friend shows as online on the caller's side. Otherwise it fails with 0x86000022 (ERROR_FRIEND_OFFLINE). Close with carrier_session_close, then carrier_session_cleanup before carrier_kill.

Offline messages (Express)

With express_nodes set, sending to an offline friend stores the message on an Express node, and the receipt reports CarrierReceipt_Offline. The recipient pulls it when it next starts and gets friend_message with offline == true. Offline friend requests travel the same way. This branch posts to and pulls from every configured Express node. The excerpt below was run against lens.beagle.chat. B sent while A was not running; A then started alone:

/* B (A is not running) */
carrier_send_friend_message(b, a_id, "sent while you were away", 24, &msgid, on_receipt, NULL);

Threading and lifecycle

  • carrier_new creates the node and loads or creates carrier.data. It does not touch the network.
  • carrier_run(carrier, interval_ms) connects to the bootstraps and runs the event loop on the calling thread. It blocks until carrier_kill is called, then saves carrier.data and returns 0. interval 0 means 1000 ms. Run it on a dedicated thread, as in the Quickstart.
  • CarrierCallbacks callbacks, message receipts and invite responses are called from inside carrier_run, on its thread. Do not block in them. Calling Carrier functions from them works: the samples above accept friends, reply to invites and join groups inside callbacks.
  • Session ICE runs on a pjnath worker thread per session, so stream and file-transfer callbacks may arrive on that thread rather than the carrier_run thread. Protect shared state.
  • Calls such as carrier_send_friend_message and carrier_invite_friend fail with ERROR_NOT_BEING_READY until the node is ready. Wait for the ready callback or carrier_is_ready().
  • Shutdown: close file transfers and sessions, call carrier_filetransfer_cleanup / carrier_session_cleanup, then carrier_kill(carrier) and join the run thread. After carrier_kill the handle is invalid.

Errors. Functions return -1 or NULL on failure and set a thread-local error code. Read it with carrier_get_error() and clear it with carrier_clear_error(). carrier_get_strerror(err, buf, len) turns the code into text, and so does the elaerr tool. A code is 0x80000000 | facility << 24 | code. The facilities are FACILITY_GENERAL (1), FACILITY_SYS (2), FACILITY_ICE (5), FACILITY_DHT (6) and FACILITY_EXPRESS (7). The codes are ERROR_INVALID_ARGS (0x01) … ERROR_BAD_FLATBUFFER (0x23), ERROR_UNKNOWN (0xFF). Examples:

add_friend error 0x81000001: [General] Invalid argument(s)
$ elaerr 0x86000022
[DHT] Friend is being offline
