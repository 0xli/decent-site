NETWORK ARCHITECTURE

Identity first. Relationship second. Transport underneath everything.

The network defaults to unreachable. A peer generates identity locally, establishes consent through friendship, discovers a path, then exposes only the application capability or service explicitly chosen.

PEER → DECENTLAN

From a friend network to a general application network

The original Peer layer was already enough for social applications: identities, friendship, presence, messages, files, and offline delivery. DecentLAN keeps that trust model and adds an IP data plane, so software written for the existing internet becomes reachable through the same relationships.

01

Carrier friend network

Public-key identity, DHT discovery, mutual friendship, online presence, messages, groups, files, and Express offline delivery for social and communication applications.

02

@decentnetwork/peer

A pure TypeScript runtime that exposes the deployed friend network to Node.js applications, agents, scripts, and services.

03

Dora naming

A normal Peer maps durable userids to human names and private 10.86.x.x addresses without becoming a central account authority.

04

DecentLAN data plane

TUN routing carries standard TCP and UDP packets. Existing software reaches a friend’s machine by private address without learning the Peer wire protocol.

The ecosystem becomes much larger when existing software can participate

Developers no longer need to rebuild every application as a native Decent client. Install AgentNet at the network edge, then keep the application protocol you already use.

The public URL does not have to be where the application runs

A small public gateway can own DNS and TLS while the expensive, stateful workload stays on private hardware. DecentLAN is the addressable path between them.

FRIEND-GATED BY DEFAULT

A 10.86.x.x address is not a public Internet address

Knowing 10.86.205.11 does not make the BTC host reachable. The gateway and host must first establish an approved friendship in the underlying Peer/DHT network; only then can DecentLAN provide a route, still limited by the services the host allows. In these examples Caddy is the trusted friend and publishes one selected HTTP service. Website visitors can reach that domain, but they do not join the private network or gain access to the host’s models, storage, SSH, Redis, or other ports.

unknown peer · unreachable→ mutual friendship →approved route · selected service

Infrastructure is optional and independently operable

Bootstrap

Introduces a new peer to the DHT.

Relay

Blindly forwards end-to-end encrypted live sessions when direct UDP fails.

Express

Stores encrypted payloads for optional offline delivery.

Dora

Provides names and private address allocation to AgentNet.

Regional exit

Offers an approved path for policy- or geography-specific traffic.

SCOPE

Honest limits

  • DHT participation and traffic timing expose metadata; this is not a metadata-free system.
  • Offline delivery depends on an Express node retention window.
  • Endpoint and key security remain the operator’s responsibility.
  • Delivery instrumentation and relay robustness are still maturing.
  • There is no token and none is required or planned in the current phase.
