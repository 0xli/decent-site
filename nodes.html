OPERATE THE NETWORK

Run infrastructure people can actually use.

There are two practical operator paths today: help identities discover one another with a C++ bootstrap node, or give a DecentLAN network controlled access to another region and the public Internet with an AgentNet exit.

Choose an operator role

01 · Discovery

Bootstrap node

Keep the Carrier DHT reachable so peers can find one another before establishing direct or relayed sessions.

02 · TCP/IP reach

Regional exit node

Publish an HTTP CONNECT proxy inside DecentLAN so approved peers can reach websites, APIs and services through your machine.

03 · Names and delivery

Dora + Express

Operate virtual-address allocation, roster discovery and store-and-forward delivery for applications that need them.

PATH 01 · C++

Run a bootstrap node

Bootstrap nodes are stable entry points for the DHT. They assist discovery; they do not own user identities or become a mandatory server for established peer relationships.

  • Ubuntu Server 16.04 or newer
  • A stable, publicly reachable host
  • CMake toolchain when building from source
Bootstrap source ↗
git clone https://github.com/0xli/Elastos.CarrierClassic.Bootstrap.git
cd Elastos.CarrierClassic.Bootstrap
./scripts/setup-ubuntu.sh

# Verify the installed daemon
sudo systemctl status ela-bootstrapd
PATH 02 · AGENTNET / DECENTLAN

Run a regional exit node

An exit is an ordinary AgentNet peer that enables the built-in CONNECT proxy. Other approved peers can route selected domains—or, when explicitly requested, all supported traffic—through its DecentLAN address. No public port forwarding is required between AgentNet peers.

Public exit

Use the default discovery and friendship policy when the exit is meant to be found by the wider network. Operators still control the hosts accepted by the proxy.

Private exit

Friend only your team or devices, then add the exit virtual IP to their routes configuration. This is the better model for a company, family or private regional gateway.

Read the exit-node guide →
sudo npm install -g @decentnetwork/lan@latest
agentnet init
agentnet proxy enable --port 8888
agentnet proxy allow-host '*'
sudo agentnet service install
agentnet identity show
agentnet proxy status
# From an approved peer, use the exit's 10.86.x.x address
curl -x http://<exit-virtual-ip>:8888 https://ipinfo.io/country

# Start client-side split routing
agentnet proxy router
# Use --all only when a full tunnel is intended

Linux firewall note: when UFW is active, allow traffic on agentnet0. Native Windows does not currently provide the TUN helper; use WSL2 for the router path.

What this enables

Regional access

Reach an API, website or TCP service from the region where the exit runs.

Remote-team LAN

Give a small team stable private addresses and access to internal services without exposing them publicly.

Home-hosted services

Keep the application on a home machine while a reachable gateway forwards an approved hostname over the private network.
